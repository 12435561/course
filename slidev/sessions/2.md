# subsystems

- robot is split up into subsystems subjectively
- done for easier reasoning and organization
- the rest of robot code asks for result, the subsystem does specific work to achieve result
- examples: shooter, drivebase, elevator, intake, feeder, hopper, climber, arm, pivot

# finite state machines

- not as scary as the name implies!
- state: what is going on with the robot/subsystem
- example state: shooting
- one "wanted state" at a time
- based on the wanted state, code chooses what actions need to be completed
